# Portfolio site (VitePress)

Start from `github.com/BootForm/vitepress-portfolio`. A portfolio without a working way to
actually get hired from it is close to useless, so this template ships a real contact form, not a
placeholder.

## Steps

1. Ask the user for a repo name if they want a new repo, then create it from the template:
   `gh repo create <name> --template BootForm/vitepress-portfolio --public --clone`. If they just
   want local files instead, clone the template directly and drop its own git history.
2. Read that repo's own `AGENTS.md` before changing anything, in particular the note on
   `<router-link>` rendering as nothing (no error) when it wraps block-level content, and why
   every dynamic link and image in this template uses `withBase()` on a plain `<a>`/`<img>`
   instead.
3. Customize `docs/.vitepress/config.mts` (name, nav) and `docs/.vitepress/theme/style.css` (the
   `--color-brand-*` block) for the user.
4. Replace the example case studies under `docs/work/` with the user's own. Each one is a
   markdown file with `title`, `description`, `image` and `order` frontmatter; adding a new file
   adds a card to both the home page and the Work page automatically, generated by
   `docs/work/work.data.ts`. `order` sorts the grid, and the home page shows the first 4. No other
   file needs to change for a new case study.
5. Use real, freely-licensed photos for each case study image (Unsplash License via Picsum
   Photos is what this template ships with), not placeholder SVGs, and not screenshots that imply
   real client work if the user hasn't done any yet.
6. If the user wants to change or extend the contact form, use the `add-contact-form` and
   `style-form` skills (from the `bootform` plugin) rather than hand-writing changes to it.
7. Before finishing: run `npm install && npm run build`, then actually open the built output and
   look at it, in both light and dark mode. A successful build is not the same as a page that
   looks right.

## Growing it

- Another page section (pricing, an FAQ, testimonials, a better hero): the `add-section` skill.
- A new kind of content with its own listing page (projects, books, team, events): the
  `add-collection` skill.

## Do not

- Use `<router-link>` for anything wrapping more than a single inline span; it silently renders
  as nothing.
- Reuse another portfolio or design system's exact component code. Every component in this
  template (the card grid, the case study layout) is original, not lifted from a third party.

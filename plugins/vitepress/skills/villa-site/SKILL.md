# Villa or holiday rental site (VitePress)

Start from `github.com/BootForm/vitepress-villa`. A property site without a working way to ask
about dates is just a brochure, so this template ships a real booking enquiry form (dates, guest
count, message), not a placeholder.

## Steps

1. Ask the user for a repo name if they want a new repo, then create it from the template:
   `gh repo create <name> --template BootForm/vitepress-villa --public --clone`. If they just want
   local files instead, clone the template directly and drop its own git history.
2. Read that repo's own `AGENTS.md` before changing anything: the one rule (every page sets
   `layout: home` or `layout: page`), the CSS-layering note, and why every runtime link and image
   goes through `withBase()`.
3. Customize `docs/.vitepress/config.mts` (name, description, nav, and `base` if the repo isn't
   called `vitepress-villa`), `scripts/generate-rss.mjs` (`SITE_URL`, `FEED_TITLE` and
   `FEED_DESCRIPTION`, which must match), and `docs/.vitepress/theme/style.css` (the
   `--color-brand-*` block).
4. Replace the five example rooms under `docs/rooms/` with the user's real ones. Each room needs
   `name`, `title`, `description`, `image`, `sleeps`, `bed`, `view` and `order` frontmatter; a new
   room file adds a card to the home page and the Rooms page automatically, generated by
   `docs/rooms/rooms.data.ts`. Keep `order` on every room, or the list order looks random.
5. Replace `docs/public/gallery/*.jpg` with the user's photos and update the `<img>` lines in
   `docs/gallery.md` to match. Replace the two example journal posts under `docs/posts/`, or delete
   them and the Journal nav link if the user doesn't want a local guide.
6. Fill in `docs/contact.md`'s location, phone or WhatsApp, and email. For the form's `action`,
   use the `add-contact-form` skill from the `bootform` plugin to get a real form ID and its claim
   link. Tell the user to claim it before the site goes live.
7. Use the property's own photos. The template's Unsplash photos (via Picsum) stand in until then,
   and must not be passed off as the property.
8. Before finishing: `npm install && npm run build`, then open the built site and look at it on a
   desktop and at phone width, in light and dark mode.

## Growing it

- Another page section (an FAQ, testimonials, a stats row, a better hero): the `add-section` skill.
- A new kind of content with its own listing page (experiences, local partners, team): the
  `add-collection` skill.

## Do not

- Add a sidebar or use `layout: doc` anywhere.
- Write a raw `<a href="/rooms/">` for an internal link inside HTML. It 404s once deployed to a
  subpath; use a markdown link or `:href="withBase('/rooms/')"`.
- Claim facilities, prices, reviews or availability the user hasn't given you.

# Blog site (VitePress)

Start from `github.com/BootForm/vitepress-blog`. VitePress ships none of a generated post list,
tag pages, or RSS on its own; this template builds all three so nobody has to hand-maintain a
list of links every time they publish.

## Steps

1. Ask the user for a repo name if they want a new repo, then create it from the template:
   `gh repo create <name> --template BootForm/vitepress-blog --public --clone`. If they just want
   local files instead, clone the template directly and drop its own git history.
2. Read that repo's own `AGENTS.md` before changing anything, in particular the CSS-layering note
   and the note on `createContentLoader`'s `excerpt` option (it needs a string separator, not
   `true`, and even then a hero image or other markup above a post's heading ends up inside the
   excerpt as broken HTML; this template uses a hand-written `description` frontmatter field
   instead, for exactly that reason).
3. Customize `docs/.vitepress/config.mts` (title, description, nav, the RSS `<link>` tag) and
   `docs/.vitepress/theme/style.css` (the `--color-brand-*` block) for the user.
4. Add real authors to `docs/.vitepress/authors.ts` and replace the three example posts under
   `docs/posts/` with the user's own. Each post needs `title`, `date`, `author`, `tags`,
   `description`, and (if the template's home/list pages are showing images) `image` frontmatter.
   A new post file shows up in the post list, the home page's Latest posts, its tag pages, and the
   RSS feed automatically, generated by `docs/posts/posts.data.ts` and
   `scripts/generate-rss.mjs`. No other file needs to change for a new post.
5. If the user wants a contact form, use the `add-contact-form` skill (from the `bootform`
   plugin) rather than hand-writing one.
6. Before finishing: run `npm install && npm run build`, then actually open the built output and
   look at it. A successful build is not the same as a page that looks right; this template alone
   has hit a silently-empty excerpt, a nested `v-for` losing its scope, and a missing footer, none
   of which produced a build error.

## Growing it

- Another page section (pricing, an FAQ, testimonials, a better hero): the `add-section` skill.
- A new kind of content with its own listing page (projects, books, team, events): the
  `add-collection` skill.

## Do not

- Pass `excerpt: true` to `createContentLoader` expecting it to split on `<!-- more -->`; it needs
  a string. Prefer a hand-written `description` field over the excerpt mechanism entirely if any
  markup sits above a post's heading.
- Write a nested `v-for` across multiple indented lines inside markdown; flatten it to one
  element per line if `{{ }}` or a loop variable starts rendering as literal text.
